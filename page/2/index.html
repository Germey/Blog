API 开发教程 Claude Code CC Switch 图形化配置教程

Claude Code 原生通过 ANTHROPIC_BASE_URL 与 ANTHROPIC_AUTH_TOKEN 两个环境变量决定请求发往哪里，把它们指向 Ace Data Cloud 即可用更低的价格、无需 Anthropic 官方订阅来使用 Claude Code。手动编辑 .claude/settings.json 对新手并不友好，而 CC Switch 提供了一个图形界面，帮你把这两个变量一键写好、并在多套供应商之间即时切换。

本文介绍如何用 CC Switch 把 Claude Code 接入 Ace Data Cloud。

什么是 CC Switch

CC Switch（官网 ccswitch.io）是一个开源、跨平台的桌面端配置管理器，用于统一管理 Claude Code、Claude Desktop、Codex、Gemini CLI、OpenCode、OpenClaw、Hermes 等多个 AI 编程工具的供应商配置。它基于 Tauri 2 构建，采用 MIT 协议开源，在 GitHub 上已获得超过 11 万 Star（参见 farion1231/cc-switch）。

它的核心价值在于（详见官方 User Manual）：

  • 免手动改配置：不用再手写 settings.json / config.toml / .env，图形界面填一次即可。
  • 一键切换：预存多套供应商，从主界面或系统托盘即时切换。
  • 原子写入：所有数据存于本地 SQLite 数据库（~/.cc-switch/cc-switch.db），采用「临时文件 + 重命名」的原子写入，避免配置损坏。

CC Switch 的工作原理是在底层动态覆盖 Claude Code 的 ANTHROPIC_BASE_URL 和 ANTHROPIC_AUTH_TOKEN，把原本发往 Anthropic 官方的请求重定向到你配置的第三方接口（本例即 Ace Data Cloud）。这一机制在社区的图文教程中也有详细说明。

申请 API Token

要使用 Claude Code，首先到 Ace Data Cloud 控制台，获取你的 API Token，留作备用。

如果你尚未登录或注册，会自动跳转到登录页面邀请你注册和登录，登录注册之后会自动返回当前页面。首次申请时会有免费额度赠送，可以免费体验 Claude Code 服务。

提示：也可以前往 Claude Messages 服务页面 点击「Acquire」获取凭证，即赠免费额度；额度不足时可在 控制台 - 通用余额 充值。

下载与安装 CC Switch

前往 CC Switch 的 Releases 页面（或直接下载最新版本），按操作系统选择对应安装包。以下安装方式均来自官方 README：

CC Switch 内置了 50+ 供应商预设，但目前不含 Ace Data Cloud，因此我们使用「Custom（自定义）」方式添加。以下步骤对应官方文档 2.1 Add Provider。

  1. 在 CC Switch 顶部切换到 Claude Code 应用。
  2. 点击右上角的 +（Add Provider）按钮打开添加面板，在 App-specific Provider 标签下操作。
  3. 在预设下拉框中选择 Custom，然后填写配置。

启用并切换供应商

添加完成后，在 Claude Code 供应商列表中找到 Ace Data Cloud 卡片，点击 Enable（启用） 即可（参见官方 2.2 Switch Provider）。你也可以从系统托盘菜单直接点击供应商名称进行即时切换，无需打开完整界面。

是否需要重启？ 根据官方 FAQ，Claude Code 支持「热切换」——切换供应商后无需重启即可生效；其余大多数工具（如 Codex、Gemini CLI）则需要重启对应 CLI 或终端。

CC Switch 启用供应商时，会把上面的配置写入 Claude Code 的配置文件（用户级 ~/.claude/settings.json）。因此，无论你在终端里运行 claude，还是使用 VS Code 的 Claude Code 扩展，都会读取到同一份配置。配置文件的位置与格式参见官方 5.1 配置文件说明。

在终端与 VS Code 中使用

CC Switch 只负责写入配置，Claude Code 本体仍需单独安装。启用供应商后：

  • 终端 CLI：安装并运行 claude 即可，完整步骤见 Claude Code 终端配置教程。进入交互界面后输入 /status，应能看到 Anthropic base URL: https://api.acedata.cloud。

  • VS Code 扩展：在扩展市场安装 Claude Code 扩展，完整步骤见 Claude Code VS Code 配置教程。由于扩展和 CLI 共享同一份配置，CC Switch 写好后 VS Code 扩展会直接复用，无需再手动填写。

  • GitHub Actions：如果你想在 CI/CD 中使用，参见 Claude Code GitHub Actions 配置教程（该场景通过 Secrets 注入变量，通常不使用 CC Switch）。

远程开发（Remote - SSH）

如果你通过 VS Code Remote - SSH 在远程服务器上开发，远程端读不到你本机的环境变量。此时可以借助 CC Switch 的本地代理（Local Proxy）功能：在 CC Switch 中开启本地代理后，它会在本机监听一个端口并转发请求；再通过 SSH 的 RemoteForward 把该端口转发到远程主机，远程的 Claude Code 即可复用本地供应商。本地代理的配置说明见官方 4.1 Proxy Service，Remote - SSH 的完整图文步骤可参考社区教程 Golden-Promise/vscode-cc-switch。

查看额度与用量

  • 通过 Ace Data Cloud 控制台 - 应用列表 查看当前账户的剩余额度。
  • 通过 Ace Data Cloud 控制台 - 使用历史 查看所有请求记录与扣费详情。

常见问题

  • 为什么无法删除当前正在使用的供应商？ CC Switch 遵循「最小侵入」原则，始终保留一个已启用配置，避免删除全部配置后 CLI 工具无法使用。详见官方 FAQ。
  • 如何切回官方登录？ 从预设列表添加一个官方登录（Official Login）供应商，切换后按照官方登录 / OAuth 流程操作即可（参见官方 Quick Start）。
  • 配置数据存在哪里？ 供应商、MCP、Prompts、Skills 等数据存于 ~/.cc-switch/cc-switch.db（SQLite），设备级 UI 偏好存于 ~/.cc-switch/settings.json，自动备份位于 ~/.cc-switch/backups/（参见官方 FAQ）。

API 开发教程 X402 价格说明

这篇文档说明用 X402 调用 Ace Data Cloud API 时，价格是怎么定的，以及它和平台普通 Credits（额度）价格是什么关系。

核心结论

X402 不是一套独立的价格体系。每个 API 调用本来就有一个以 Credits 计的成本，这是所有计费方式（API Token 扣额度、账户余额、X402 链上支付）共用的唯一价格来源。X402 只是把这个 Credits 成本按一个固定汇率换算成链上 USDC：

1 Credit = 0.095215 USDC（即 95215 atomic USDC，USDC 为 6 位小数）

也就是说：

这个汇率不是凭空设定的，它等于平台 最优档（大额）Credits 单价。所以用 X402 付费 ≈ 用最优档单价买 Credits 再消费，没有 X402 溢价，反而直接享受最便宜的 Credits 单价，且无需预充值、无需 API Token。

计价基准

项目 值 说明
换算汇率 1 Credit = 0.095215 USDC 平台统一设定的固定汇率
atomic 单位 1 Credit = 95215 atomic USDC USDC 6 位小数，atomic = floor(credits × 0.095215 × 1e6)
最小扣费 1 atomic USDC（$0.000001） 即使成本极低，也至少结算 1 atomic
计价币种 USDC Base / SKALE 为 ERC-20 USDC，Solana 为 SPL USDC

换算由平台统一完成，金额对所有支持的网络（Base、SKALE、Solana）一致；不同网络只是资产合约和签名方式不同，价格相同。

和普通 Credits 单价的关系

平台 Credits 按「用量越大、单价越低」的阶梯出售。X402 按调用计费时，统一使用阶梯最优档单价：

购买/支付方式 大致 Credits 单价 说明
入门 / 小额充值 约 $0.13 / Credit 列表价，小额买 Credits 时的单价
大额 / 最优档 $0.095215 / Credit 最便宜的单价
X402 按调用付费 $0.095215 / Credit 始终等于最优档单价

换句话说，X402 把每次调用都按最优档 Credits 单价结算。小额充值买 Credits 的用户，单价会高于 X402；大额充值用户的单价才和 X402 一致。

两种价格形态：exact 与 upto

X402 的 402 响应里，maxAmountRequired 就是你要签名的金额。它有两种形态：

  • exact（固定价）：请求处理前价格就能确定（图片、视频、音乐、搜索、订单支付）。maxAmountRequired = 该调用 Credits 成本 × 0.095215，即该次调用的应付金额（与成功响应里的 cost.amount 一致）。
  • upto（用量后置计量）：聊天补全这类「响应结束才知道用了多少 token」的接口。maxAmountRequired 是一个上限（按该模型设定的上限额度换算：上限 Credits × 0.095215），实际按真实用量结算，且不超过上限。

关于这两种 scheme 的协议细节见 exact 与 upto 计费方案。下面只讲价格。

什么是 MCP？

MCP（Model Context Protocol）是 Anthropic 推出的开放协议，让 Claude 这类模型可以通过标准接口调用外部工具。简单理解：给 Claude 装上插件能力。

  • 单个短链生成（shorturl_create）
  • 批量短链生成（shorturl_batch_create）
  • 查询 API 信息 / 配额（shorturl_get_api_info）
  • 查阅使用指南（shorturl_get_usage_guide）

整套接入只需一个 URL，剩下交给 Claude。

API 开发教程 X402 `exact` 与 `upto` 计费方案

Ace Data Cloud X402 目前使用两类 scheme：exact 和 upto。它们解决的是不同计费问题。

exact

exact 表示本次请求在进入上游 API 前就能确定价格。客户端签名的金额就是最终扣款金额。

适合：

  • 固定价格的图片生成；
  • 固定价格的视频任务创建；
  • 固定价格的搜索或工具 API；
  • 订单支付。

EVM exact 使用 USDC EIP-3009 TransferWithAuthorization：

Facilitator 在 /verify 阶段验证签名和金额，在 /settle 阶段把这笔授权提交到链上。

upto

upto 表示客户端授权一个最大上限，Ace Data Cloud 在请求完成后按实际用量结算，实际扣款不能超过上限。

适合：

  • 聊天补全：最终价格取决于 prompt tokens 和 completion tokens；
  • 流式响应：真实输出长度结束后才知道；
  • 未来的后置计量 API。

异步回调

由于 Riffusion Audios Generation API 生成的时间有时候会相对较长，如果 API 长时间无响应，HTTP 请求会一直保持连接，导致额外的系统资源消耗，所以本 API 也提供了异步回调的支持。

请求头

Header 必填 说明
authorization 是 Bearer {token}，{token} 是在本平台申请的密钥。
content-type 是 application/json。
accept 否 application/json。
model 否 TTS 模型，可选 s1 或 s2-pro，默认 s2-pro。s2-pro 表现力更强；s1 更稳定，长文本不易跑偏。

请求体字段

字段 类型 必填 说明
text string 是 要合成的文本，非空字符串。
format string 是 输出音频格式。当前必须显式传值，可选 mp3 或 pcm。即使官方文档列出 wav、opus，本接口上游也会返回 400 Input should be 'pcm' or 'mp3'。

references object[] 否 内联参考样本，结构与上游一致，每项含 audio 与 text。与 reference_id 二选一。
sample_rate integer 否 采样率，常用 16000、22050、44100。format=mp3 默认 44100。
mp3_bitrate integer 否 MP3 码率，可选 64、128、192。仅 format=mp3 生效。
prosody object 否 韵律覆盖，支持 speed（语速，1.0 为原速）和 volume（音量增益 dB）。例如 {"speed":1.2,"volume":0}。
chunk_length integer 否 上游分片长度，默认上游决定。
temperature number 否 采样温度，范围约 0.0–1.0。
top_p number 否 top-p 采样参数。
latency string 否 normal 或 balanced，缺省由本接口自动补 normal（直接传空字符串上游会拒绝）。
normalize boolean 否 是否对文本做归一化。
