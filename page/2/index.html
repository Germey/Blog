技术教程 OpenCode 对接 Google 搜索 MCP

📘 Overview：OpenCode MCP Overview →

你在远程服务器上用 OpenCode 排查一个 OOM 问题，看到一条不太熟悉的内核日志。以前只能复制错误信息、断开终端、切到本地浏览器搜索，再切回来。接上 Serp MCP Server 后，OpenCode 可以直接在终端里搜 Google，不需要离开命令行就能完成“看日志 → 搜资料 → 改代码”整条链路。

Google 搜索 MCP 适合在 OpenCode 里调试生产问题、做技术选型调研、查官方文档、找 GitHub issue，以及任何需要“搜索网页才能继续工作”的场景。

获取 API Token

使用 Google 搜索 MCP Server 之前，需要先准备一个 Ace Data Cloud API Token。OpenCode 和 Claude Code 共用一套 Token，获取流程一样：

  1. 打开 Ace Data Cloud 控制台 - 应用列表，获取您的 API Token，留作备用。
  2. 如果你尚未登录或注册，会自动跳转到登录页面；登录注册之后会自动返回当前页面。
  3. 首次申请时会有免费额度赠送，可以先免费体验 Google 搜索 MCP 服务。

一个 Token 可以使用 Ace Data Cloud 提供的全部 MCP Server，无需为 Google 搜索 单独申请。文档和截图里建议只展示脱敏形式，例如 YOUR_ACEDATACLOUD_API_KEY，不要把完整 Token 贴到公开仓库、Issue、截图或聊天记录里。

想用 Claude Desktop / Claude.ai 网页版直接 OAuth 一键授权？请看 Google 搜索 MCP 的 Claude.ai / Desktop 教程。

配置 OpenCode

OpenCode 用一份 opencode.json 描述所有 MCP Server，文件可以放在两处，按下面”作用范围”选一种即可。两种位置的字段结构完全相同，区别只是优先级。

强烈推荐先把 Token 写到环境变量里：

然后在 opencode.json 里用 {env:ACEDATACLOUD_API_KEY} 占位符引用，避免真实 Token 写进文件。

全局：所有项目共用

文件位置：~/.config/opencode/opencode.json，适合”我自己的机器，一次配好，所有项目都能用”。

⚠️ "oauth": false 不可省略。AceData 的 MCP Server 使用 Bearer Token 鉴权，不走 OAuth 流程；OpenCode 默认会把 401 当成 OAuth 挑战自动重定向，导致 opencode mcp list 出现 SSE error: Non-200 status code (401)。显式声明 "oauth": false 让 OpenCode 直接以 Authorization: Bearer ... 调用，opencode mcp debug serp 也会回显 OAuth explicitly disabled，代表生效。

项目级：仅当前项目生效

文件位置：当前项目根目录下的 opencode.json，会覆盖全局配置。适合团队共享、单仓库定制，或者只在某个项目里临时启用某个 MCP。

如果项目级 opencode.json 会被提交到 Git，请确保用 {env:ACEDATACLOUD_API_KEY} 占位符而不是真实 Token，避免泄露。

💡 如果 Shell 里的 .env 没有显式 export，需要用 set -a && source .env && set +a 才能把变量传给 OpenCode 进程，否则 opencode debug config 会显示 "Authorization": "Bearer "（占位符没解析）。

什么是 MCP？

MCP 是 Anthropic 推出的开放协议，让 Claude 这类模型可以通过标准接口调用外部工具。简单理解：给 Claude 装上插件能力。

Ace Data Cloud 把 Suno 的核心能力封装成了一个远程 MCP Server，挂上去之后 Claude 就能直接：

  • 一句话生成完整歌曲（含人声 + 伴奏）
  • 自定义歌词、标题、风格、BPM
  • 从指定时间点续写已有歌曲
  • 翻唱、混搭、分离人声与伴奏
  • 生成歌词、管理声音风格 Persona

整套接入只需一个 URL，剩下交给 Claude。

API 开发教程 X402 网络与支付方式

Ace Data Cloud X402 当前围绕 USDC 结算，支持 EVM 和 Solana 两类链。不同网络的签名方式、资产地址、gas 行为和适用场景不同，接入前需要先选好网络。

网络标识使用 CAIP-2

x402 v2 的 accepts[].network 是 CAIP-2 标识，不是 base、skale 这类简称。客户端匹配网络时必须按 CAIP-2 字符串比较：

网络 CAIP-2 标识
Base eip155:8453
SKALE Base eip155:1187947933
Solana mainnet solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp

支持矩阵

网络 scheme 资产 签名方式 适用场景
Base exact Base USDC EIP-3009 TransferWithAuthorization 默认推荐，钱包和流动性支持成熟。
Base upto Base USDC + Permit2 Permit2 PermitWitnessTransferFrom 聊天、模型等后置计量 API。
SKALE exact SKALE bridged USDC EIP-3009 TransferWithAuthorization 低 gas 成本，适合 EVM 支付验证和低成本调用。
Solana exact Solana USDC SPL TransferChecked Solana 钱包、Agent 或链上应用场景。

upto 目前只在 Base 上提供。实际可用项以 API 返回的 accepts 为准。你也可以查看 Facilitator：

Facilitator /supported 的返回：

结果说明：

  • Base、SKALE 和 Solana 的 exact 是固定金额支付路径。
  • 只有 Base 提供 upto 后置计量路径，依赖 Permit2 approve。
  • upto 条目里的 extra.facilitatorAddress 是客户端签名时要写入 witness 的地址，必须和服务端返回值一致。

Base

Base 使用官方 USDC 合约：

exact 方案中，客户端签署 EIP-712 TransferWithAuthorization。签名内容包括：

  • from：付款钱包地址
  • to：Ace Data Cloud 收款地址
  • value：本次支付金额
  • validAfter / validBefore：签名有效时间窗口
  • nonce：32 字节随机 nonce

Facilitator 验证签名后，会在链上调用 USDC 的 transferWithAuthorization 完成转账。

Base 是最推荐的正式接入网络，尤其适合 upto 后置计量，因为 Permit2、USDC 和钱包生态都更成熟。

SKALE 使用 bridged USDC，签名方式与 Base 类似，也是 EIP-3009。它适合低 gas 成本的 EVM 支付场景；实际调用仍以 API 返回的 accepts 为准。

Solana

Solana 使用 SPL USDC TransferChecked。客户端会构造一笔转账交易，签名并提交，之后把交易签名或序列化交易放入 PAYMENT-SIGNATURE envelope。

Solana 的特点：

  • 使用 Solana wallet adapter 或 base58 secret key；
  • 资产是 Solana USDC mint；
  • 当前只支持 exact；
  • Facilitator 会校验 transfer instruction 的 mint、destination、authority 和 amount。

如果使用钱包 fee payer 模式，钱包会直接提交交易，Facilitator 负责确认交易并返回 settlement 结果。

如何选择

你要做什么 推荐网络
快速跑通最小链路 SKALE exact 或 Base exact
面向普通 Web3 用户 Base
做聊天补全等后置计量 Base upto
Solana 生态应用 Solana exact
低成本 EVM 支付验证 SKALE exact

无论选择哪条链，都不要在客户端硬编码价格。价格由服务器返回的 accepts[].maxAmountRequired 决定。
