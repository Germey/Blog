用 Ace Data Cloud Studio 从一张分镜做起：《最后一盏灯》创作实录

作者 崔庆才 发表于 2026-10-06 分类于 技术教程 阅读次数： 本文字数： 6.6k 阅读时长 ≈ 6 分钟
从 Claude 开源 MV 的分镜方法出发，在 AceData Studio 实际生成原创三格分镜、16:9 首帧和亮灯版参考图，再拆解图生视频的提交、检查与迭代。附原始视频案例、真实图片结果和可复制提示词，明确区分已完成创作与待执行的视频步骤。

一座灯塔熄灭了。海面很安静，一个小机器人站在门口，抬头看了看黑下来的灯室。

它想做的事很小：让这盏灯重新亮起来。

这就是我们今天的创作题目——《最后一盏灯》。不用先写宏大的世界观，不用凑几十个镜头，也不必上来就生成三分钟 MV。先把一个动作、一段因果和一个结尾做清楚。

本次通过 AceDataCloud 的 GPT Image 能力实际生成的静态首帧，也作为本文封面。不是视频截帧。

先说明本篇的完成范围。 本次实际完成了三格概念分镜、独立首帧、参考图编辑，以及辅助视觉检查；没有执行新的 Seedance 视频生成，也没有制作最终配乐成片。下面把已完成的图片创作与可继续执行的视频操作分开标注。文中的播放器展示已有的公开案例，不冒充《最后一盏灯》的结果。文中提示词为便于阅读整理的中文版，不保证重复生成相同图片。

先看一个源案例：值得学的不是“一句话”，而是制作顺序

JohnHeibel 的开源项目 PDoomVideo，为《I’m Upping My P(doom)》制作了程序化 MV。项目 README 写明：它经过两轮生成，使用 p5.js、p5.brush 绘制，通过 headless Chrome 渲染帧，再用 FFmpeg 编码。仓库里还保留了分镜、角色、章节和时间线代码。[1]

来源：JohnHeibel / PDoomVideo，作者公开的 README 演示素材，外链引用，仅用于案例讲解；不是 AceData Studio 生成结果。

观看作者发布的原始 MV：I’m Upping My P(doom) · 阅读项目源码

作者后来整理的 ClaudeAnimationBase 更有教学价值：先给分镜，再逐镜头制作，渲染检查图，发现问题后继续修改。它的动画指南特别强调：每个镜头都要发生一件事，并给观众留出看见和理解的时间。[2][3]

我们借用的是这套先设计、再制作、再检查的方法，而不是宣称下面的图片和视频也由代码逐帧绘制。

本文的路线是：

Studio 对话梳理故事 → GPT Image 生成与修改图片 → 按需进入 Seedance 图生视频 → 观看样片并提出具体修改。

这是一条结合生成模型的创作路线，与原项目的纯程序绘制不同。也不要把网上所有“Claude 做的视频”混为一谈：例如 anabology 的公开帖就明确提到了 Midjourney。[4]

第一步｜进入 Studio，但先别按生成

打开 AceData Studio，登录后，从首页创作分类或能力导航进入聊天、图片、视频等工作区。官方说明也建议先用小任务验证流程，再做高分辨率、长视频或批量生成。[5]

Studio 官方文档中的界面图；布局、功能入口和模型选项可能随版本、账号与站点配置变化，以当前页面为准。

本篇主要用三个入口：

要做什么 Studio 入口 本次是否执行
讨论故事、整理提示词 首页的 AI 对话 本文提供可复制创作要求
生成分镜、首帧，修改参考图 GPT Image 图片工作区 已通过对应连接器执行
把首帧变成动态样片 Seedance 视频工作区 提供后续操作，未提交新任务

如果习惯在助手对话中完成任务，可以在 连接器页面 启用所需能力。图片生成与视频生成是不同服务；连接图片服务，不代表已经授权视频服务。

本篇不假设 Studio 自带通用剪辑时间线，也不假设普通对话自动拥有本地 Chrome、Node.js 或 FFmpeg。 如果你要逐行复现原开源项目，需要另行准备它的执行环境，不是把仓库地址贴进普通聊天就算完成渲染。

写一张创作任务卡

在开始前，把下面这段发给 Studio 助手，或保存在你的项目笔记里：

注意最后一句。先讨论方案，不等于马上提交生成。 先把故事规模收住，后续每一次生成才有明确目的。

第二步｜把“温暖治愈”翻译成观众看得见的动作

“做一支温暖治愈的短片”很容易得到漂亮但空泛的画面。我们给它增加一条清楚的因果链：灯不亮 → 机器人操作 → 灯亮了。

这是本篇采用的文字分镜。时间是编辑计划，不是视频模型保证精确执行的时间码。

计划时间 画面事件 观众要理解的内容 检查重点
0—4 秒 机器人抬头看没有发光的灯室 它发现了问题 一开始不能已经亮灯
4—9 秒 机器人靠近门旁低位开关，用身体轻推 它主动触发变化 开关够得到，动作与结果有先后
9—15 秒 灯室亮起，暖光照向右侧海面 它成功了 光束不过曝，结尾留出停顿

为什么不设计“爬楼梯、打开机器、维修线路、跑回门口”？因为每多一个动作，就多一个需要表现清楚的空间关系。第一次做短片，先让一个动作成立。

实际生成：三格概念分镜

在 GPT Image 工作区选择当前可用的图像模型。本次使用 gpt-image-2，生成尺寸为 1536 × 1024。若你的页面只显示比例预设，选择接近的横向比例即可，不必为了教程中的数字寻找不存在的输入框。

这张图没有直接过关：我们发现了什么？

图片生成成功，不代表故事设计已经成功。把概念图与下一步的独立首帧并排检查时，辅助视觉检查指出：概念分镜中的操作镜头，把开关画得较大、较高；角色眼睛的可见数量也随角度与简化方式变化。它适合讨论情节，但还不适合当作严格一致的角色设定表。

因此，后续制作采用更简单的操作设定：开关在门旁低位，机器人用身体就能轻推；角色外观以独立首帧为准。

这不是把概念图包装成完美结果，而是明确它的用途和缺陷。不要把整张三格图直接当作图生视频的起始画面。

第三步｜生成独立首帧：先把场景和角色定下来

分镜负责讲清楚故事，首帧负责告诉后面的生成任务“从什么画面开始”。两者不要混用。

仍然在 GPT Image 工作区，新建一张 16:9 单场景图片。本次实际使用 1536 × 864，并明确要求不要分格。

本次真实图片输出。文字提示是创作要求，是否满足仍需检查；不能因为提示里写了“两只眼睛”，就跳过看图。

第一轮只检查四件事：

  • 是否是一张连续场景，而不是三格拼图？
  • 灯塔是否真的没有发出光束？
  • 机器人是否仍然容易辨认，开关是否靠近它？
  • 右侧是否有空间容纳后面的灯光变化？

保存这张图片及其生成要求。后续修改尽量带上它，不要每次只用文字重新抽一张“差不多的灯塔”。

第四步｜不是重画一张，而是把同一座灯塔点亮

现在我们需要一个结尾参考：不是换岛、换机器人，而是在同一场景里开灯。

在支持参考图编辑的 GPT Image 流程中，上传或选择刚才的首帧；如果从 Studio 助手操作，附上图片或可访问的图片地址，并明确“编辑这张图”。不要只发一段新的文字描述。

本次以首帧为输入，实际执行了图像编辑，得到下面的亮灯版：

辅助视觉比对认为，主要布局和机器人外观基本保留，明显变化集中在灯光及附近增亮区域。这不是逐像素一致性检测，也不能证明未来视频中的动作一定稳定。 人工仍应放大检查门、屋顶、角色边缘和海岸线。

这次我们拿到的不是成片，而是一个更明确的创作条件：从“灯灭”开始，到“灯亮”结束。

第五步｜进入视频工作区：先做一个五秒样片

以下是可继续执行的操作。本次没有提交这一步的新视频任务。

在做自己的样片前，可以先看一个已有的 Studio 相关视频示例，理解“小动作、简单场景、克制运镜”怎样被写进要求。

打开 Seedance 纸船示例视频

来源：AceDataCloud 的 Seedance 使用文档。该视频是已有示例，不是本次生成；文档给出的创作方向是黄昏水面的纸船、细小涟漪和缓慢推进。[6]

回到我们的灯塔。先不要把全部三段情节塞进五秒钟。第一段样片只测试：灯室从暗到亮，海面有一点运动，角色和建筑不变形。

方式 A：直接使用视频工作区

  1. 打开 Seedance 工作区。
  2. 选择当前页面支持图生视频的模型与模式。
  3. 将上面的独立首帧作为起始图片，不要上传三格分镜拼图。
  4. 如果所选模式明确支持首尾帧，再把亮灯版设为尾帧；如果没有该选项，先只用首帧，把亮灯版留作人工验收参考。
  5. 首轮选择页面支持的低成本测试规格，例如 5 秒、720p、16:9。若当前模型不接受这些组合，按页面允许值调整。
  6. 检查价格、音频选项和素材后再提交。

首帧、尾帧、角色参考不是同一种输入。 官方文档说明，首尾帧模式与多模态参考模式不能混用；不同模型的支持范围也不同。[6] 不要为了把两张图都塞进去，随意选择一个不匹配的参考类型。

样片提示词：

这段样片没有包含推开关的完整动作。它先验证视觉稳定性；通过后，再单独处理更难的因果动作，或尝试页面支持的较长时长。

方式 B：在 Studio 助手里操作

连接 Seedance 后，也可以把首帧、提示词和规格交给助手：

任务 ID 代表“已受理”，不是“已成片”。等待期间保留任务记录；如果出现失败，先确认原因，再决定是否修改参数重试。

第六步｜验收时不要说“再好看一点”

真正有用的反馈，应该指出哪一段、哪个对象、什么问题。这与开源动画指南里的“实际看渲染结果，再修复”是同一种工作习惯。[3]

拿到自己的样片后，按下面的表检查：

观察位置 要检查什么 发现问题后的具体反馈
开头 首帧是否被遵守 开头保持灯室关闭，不要第一帧就亮灯
变化发生处 灯光是否渐亮、是否过曝 减少亮灯强度，保留海面纹理，不要白色闪屏
全程 门窗、屋顶、机器人是否变化 保留原图结构，不新增手臂，不改变眼睛数量
结尾 结果是否有停留时间 光束稳定后留出短暂停顿，不要刚亮就结束

如果接下来做完整故事，再增加一个检查项：灯光有没有先于机器人操作发生？ 如果因果顺序乱了，先减少动作，别继续堆特效。

可以这样写修改要求：

这里的“只修正”是你的目标，不是对模型局部编辑能力的保证。有的模式需要重生成，有的支持参考视频编辑；先核实当前工具能做什么。重新生成的视频也可能改变其他区域，仍需复查。

第七步｜从样片走向完整短片，先守住边界

样片通过后，再尝试前面的约 15 秒故事计划：发现问题、靠近开关、触发灯光、留在门旁。优先让一个连续场景成立，不急着加入复杂的多镜头调度。

如果你选择分别制作三段素材，需要后续组接。本篇没有验证 Studio 内置通用时间线剪辑功能，因此不写“拖进去自动剪好”。可使用你已经确认可用的剪辑工具；如果要改用自动成片服务，须另行核实它能否接收这些素材，以及是否会重新生成画面。

配乐也建议放在后面。如果你的 Studio 已启用 Suno，可以尝试这样的方向：

这是可选提示，不是本次已执行步骤；不要把“想要 15 秒配乐”当作模型必然精确输出 15 秒。截取、淡入淡出和音画同步，需要在确实支持这些功能的工具中完成。音乐不是越满越好——灯亮起来之后，留一点海浪声，往往比再加一层鼓点更适合这个故事。

收工前，留下的不应该只有一张好看的图

建议为这个小项目保留六样东西：

  • 创作任务卡：故事、角色、风格和限制；
  • 文字分镜：每段发生什么、观众要看懂什么；
  • 三格概念图：用于讨论，不充当严格角色设定；
  • 独立首帧与亮灯版：作为起点与验收参考；
  • 视频任务记录：模型、模式、参数、任务 ID 与结果；
  • 修改记录：哪个问题改过，哪些仍未解决。

本次已经得到三张原创图片，也做出了一项具体取舍：概念分镜只用来讨论故事，实际画面以带低位开关的独立首帧为准，再参考它编辑亮灯版。 这比“让 AI 自动做一切”更像真正的创作——看见差异，决定保留什么，再把下一步交代清楚。

公开的源案例展示了另一条值得探索的道路：程序可以成为动画工程的一部分。但对第一次使用 Studio 的创作者来说，不必一开始就搭建渲染器。先从一个小故事、一张可用首帧和一次可检查的变化开始。

今天的目标不是让 AI 拍大片，而是让这盏灯，按你设计的方式亮起来。
