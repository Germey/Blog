技术教程 OpenCode 对接 Seedream MCP

📘 Overview：OpenCode MCP Overview →

Seedream 对中文 prompt 的理解、商品图和海报场景的表现一直很稳定，尤其在“按描述编辑现有图片”上几乎可以直接交付给设计同学。在 OpenCode 里接上 Seedream MCP Server 之后，你可以直接用中文描述自己想要的图，也可以让 AI 修改你贴进来的现有图片。

Seedream MCP 适合做电商商品图、活动海报、社交媒体配图，以及修改海报上的文字、调整画面元素等“二次编辑”场景。

获取 API Token

使用 Seedream MCP Server 之前，需要先准备一个 Ace Data Cloud API Token。OpenCode 和 Claude Code 共用一套 Token，获取流程一样：

  1. 打开 Ace Data Cloud 控制台 - 应用列表，获取您的 API Token，留作备用。
  2. 如果你尚未登录或注册，会自动跳转到登录页面；登录注册之后会自动返回当前页面。
  3. 首次申请时会有免费额度赠送，可以先免费体验 Seedream MCP 服务。

一个 Token 可以使用 Ace Data Cloud 提供的全部 MCP Server，无需为 Seedream 单独申请。文档和截图里建议只展示脱敏形式，例如 YOUR_ACEDATACLOUD_API_KEY，不要把完整 Token 贴到公开仓库、Issue、截图或聊天记录里。

想用 Claude Desktop / Claude.ai 网页版直接 OAuth 一键授权？请看 Seedream MCP 的 Claude.ai / Desktop 教程。

配置 OpenCode

OpenCode 用一份 opencode.json 描述所有 MCP Server，文件可以放在两处，按下面”作用范围”选一种即可。两种位置的字段结构完全相同，区别只是优先级。

强烈推荐先把 Token 写到环境变量里：

然后在 opencode.json 里用 {env:ACEDATACLOUD_API_KEY} 占位符引用，避免真实 Token 写进文件。

全局：所有项目共用

文件位置：~/.config/opencode/opencode.json，适合”我自己的机器，一次配好，所有项目都能用”。

⚠️ "oauth": false 不可省略。AceData 的 MCP Server 使用 Bearer Token 鉴权，不走 OAuth 流程；OpenCode 默认会把 401 当成 OAuth 挑战自动重定向，导致 opencode mcp list 出现 SSE error: Non-200 status code (401)。显式声明 "oauth": false 让 OpenCode 直接以 Authorization: Bearer ... 调用，opencode mcp debug seedream 也会回显 OAuth explicitly disabled，代表生效。

项目级：仅当前项目生效

文件位置：当前项目根目录下的 opencode.json，会覆盖全局配置。适合团队共享、单仓库定制，或者只在某个项目里临时启用某个 MCP。

如果项目级 opencode.json 会被提交到 Git，请确保用 {env:ACEDATACLOUD_API_KEY} 占位符而不是真实 Token，避免泄露。

💡 如果 Shell 里的 .env 没有显式 export，需要用 set -a && source .env && set +a 才能把变量传给 OpenCode 进程，否则 opencode debug config 会显示 "Authorization": "Bearer "（占位符没解析）。

API 开发教程 Coze 自定义模型接入总览

路线 状态 指南
OpenAI Chat Completions 实验性 Chat 配置
OpenAI Responses 实验性 Responses 配置
Anthropic Messages 实验性 Messages 配置

“实验性”表示官方能力和配置入口已确认，但不同 Coze 区域、版本或套餐可能显示不同表单，Ace Data Cloud 仍需按协议完成固定版本验证。不要把某一条协议成功外推到另外两条。

配置原则

  • Base API URL 优先填写文档给出的 base；不要重复追加客户端会自动补齐的 endpoint path。
  • API Key 使用你的 Ace Data Cloud API Token。
  • Model 使用模型目录中与所选协议兼容的精确模型 ID。
  • 普通文本成功后，还应验证 streaming 和工具调用。

API 开发教程 赠送充值卡

在「我的应用」选择可赠的 Usage 余额，进入独立创建页，设定每张面额、份数、领取截止时间、卡面样式和可选的指定领取人，即可创建一条分享链接。可按用户 ID、用户名、邮箱或手机号精确查找领取人；不指定领取人则公开领取。新建卡只支持流光丝带、花语、晨曦和庆典彩带四种主题封面，页面会预览实际卡面；也可开启自定义封面并上传图片。创建接口不再接受旧主题，已创建的卡片继续保留原来的封面样式。中文祝福语旁的地球开关可启用自动翻译：创建后逐步生成其他语言，在翻译完成前展示中文原文。创建时一次性扣除全部卡片额度；领取人登录后每批最多领取一张，领取成功立即进入对应的通用或同服务余额。指定了领取人的卡片仅这些用户可领；公开卡片则先到先得。

创建人可以结束赠送，未领取的额度退回原 Application；已领取的不会撤销。到期的未领额度由后台定时退回。可赠额度以来源 Application 的当前剩余额度为准，不要求额度来自付费订单；已使用和已分配的额度已从该余额扣除。创建时在数据库事务中再次检查并预留总额，避免并发超额赠送。若来源或目标账户存在限制、可赠额度不足或来源账户设置了到期时间，创建或领取会被拒绝。不同服务与计费单位之间不进行折算。

卡片链接仅供分享展示和领取；不要把它当作付款凭据。上传封面只接受符合平台限制的图片。

领取成功后，在支持 Apple 钱包的 iOS 设备上可从领取页选择「加入 Apple 钱包」，并在 iPhone 的卡片预览中确认添加。使用领取该卡片的账户重新打开或刷新分享链接时，页面会恢复自己的领取记录和钱包入口，不会再次增加余额。未登录或未领取该卡片的账户不能下载这张钱包卡片。

钱包卡面沿用赠送卡的主题或自定义封面与品牌标识。Apple 钱包使用原生商店卡布局：封面展示在卡片的图片区域，金额与计费单位合并为单行顶部字段。商店卡图片仅覆盖 iOS 预留的图片区域，不支持整张卡片铺满背景图。卡片外形、高度、留白与文字字体由 iOS 控制，不能指定为网页卡片的横版比例，也不能完整复刻网页排版。已添加的旧卡片可从领取页重新下载并确认更新卡片，以使用新的卡面。

API 开发教程 ADSL 代理对接说明

在爬虫与反爬虫斗争愈演愈烈的情况下，各大网站和 App 的风控检测越来越强，其中一项就是 IP 封禁。

为了解决 IP 封禁的困扰，一个有效的方式就是设置代理，设置代理之后，爬虫可以借助代理的 IP 来伪装自己的真实 IP 地址，从而突破反爬虫的限制。

但代理的质量有高有低，比如市面上的免费代理，几乎绝大多数都是不可用或者被封禁的状态，而有些付费普通代理也陆续被加入了各大网站和 App 的风控黑名单。因此，现在可以用作高质量数据爬爬取的代理越来越少了，目前市面上质量较高的代理主要有独享代理、ADSL 代理、移动蜂窝代理这几种类型。

本代理服务就是基于 ADSL 搭建的轮换代理服务，本文档会介绍此服务的申请和使用方法。

ADSL 代理介绍

ADSL，英文全称是 Asymmetric Digital Subscriber Line，即非对称数字用户环路。ADSL 通过拨号的方式上网，拨号时需要输入 ADSL 账号和密码，每次拨号就更换一个 IP。IP 分布在多个 A 段，如果 IP 都能使用，则意味着 IP 量级可达千万。

基于 ADSL 方式搭建的代理相比机房搭建的普通代理来说，有两个优势：一是线路基本都是移动、联通、电信，更贴近于居民日常上网线路，所以 IP 被封禁的概率会低一些。二是 IP 量级大，IP 量级越大，每个 IP 被封禁的概率就越小。

本代理服务背后是基于一个大规模的 ADSL 代理池，主要覆盖中国线路，线路主要来自移动、联通、电信等拨号 VPS 服务器，覆盖中国 100 多城市，出口 IP 约每日 30 万。支持市面上几乎所有网站和 App 的数据请求，代理质量很高，能够很大减小风控概率。
