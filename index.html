API 开发教程 获取 AceDataCloud 平台文档详情

通过文档 UUID 或 alias 获取单篇文档的完整内容和导航关系。已知 alias 时可以直接请求，无需先从列表筛选。

接口概览

项 内容
方法 GET
URL https://platform.acedata.cloud/api/v1/documents/{id_or_alias}
鉴权 公开；知道 UUID 或 alias 即可直接读取

参数

  • id_or_alias：文档 UUID、当前 alias，或保留在 redirect_from 中的旧 alias。
  • lang：可选语言提示；也可使用 Accept-Language。最终内容语言以响应 content_locale 为准。

响应说明

详情使用单个对象响应，当前包含：

  • id、alias、redirect_from、name、title、type、rank、tags；
  • content、content_mode、content_locale、content_hash；
  • parent、sibling 和按 rank 排序的公开 children 摘要；
  • api / dataset / integration 关联，以及 agent（存在时）。

响应没有 breadcrumbs 字段。构建面包屑时可从 parent 继续读取其详情，或使用已缓存的文档目录关系。

错误处理

  • ID/alias 不存在或不符合当前站点可见性：404。private 只控制列表可见性，不阻止知道链接的人直接读取，不能作为保密边界。
  • 当前路由使用无尾斜杠形式；不要依赖代理层自动补斜杠。

API 开发教程 赠送充值卡

在「我的应用」选择可赠的 Usage 余额，进入独立创建页，设定每张面额、份数、领取截止时间、卡面样式和可选的指定领取人，即可创建一条分享链接。可按用户 ID、用户名、邮箱或手机号精确查找领取人；不指定领取人则公开领取。新建卡只支持流光丝带、花语、晨曦和庆典彩带四种主题封面，页面会预览实际卡面；也可开启自定义封面并上传图片。创建接口不再接受旧主题，已创建的卡片继续保留原来的封面样式。中文祝福语旁的地球开关可启用自动翻译：创建后逐步生成其他语言，在翻译完成前展示中文原文。创建时一次性扣除全部卡片额度；领取人登录后每批最多领取一张，领取成功立即进入对应的通用或同服务余额。指定了领取人的卡片仅这些用户可领；公开卡片则先到先得。

创建人可以结束赠送，未领取的额度退回原 Application；已领取的不会撤销。到期的未领额度由后台定时退回。可赠额度以来源 Application 的当前剩余额度为准，不要求额度来自付费订单；已使用和已分配的额度已从该余额扣除。创建时在数据库事务中再次检查并预留总额，避免并发超额赠送。若来源或目标账户存在限制、可赠额度不足或来源账户设置了到期时间，创建或领取会被拒绝。不同服务与计费单位之间不进行折算。

卡片链接仅供分享展示和领取；不要把它当作付款凭据。上传封面只接受符合平台限制的图片。

领取成功后，在支持 Apple 钱包的 iOS 设备上可从领取页选择「加入 Apple 钱包」，并在 iPhone 的卡片预览中确认添加。使用领取该卡片的账户重新打开或刷新分享链接时，页面会恢复自己的领取记录和钱包入口，不会再次增加余额。未登录或未领取该卡片的账户不能下载这张钱包卡片。

钱包卡面沿用赠送卡的主题或自定义封面与品牌标识。Apple 钱包使用原生商店卡布局：封面展示在卡片的图片区域，金额与计费单位合并为单行顶部字段。商店卡图片仅覆盖 iOS 预留的图片区域，不支持整张卡片铺满背景图。卡片外形、高度、留白与文字字体由 iOS 控制，不能指定为网页卡片的横版比例，也不能完整复刻网页排版。已添加的旧卡片可从领取页重新下载并确认更新卡片，以使用新的卡面。

钱包卡片展示的是已领取额度的静态凭证，不显示实时余额，也不能用于再次兑换或转账。卡片下方的二维码打开平台应用余额页面，查看实时余额需登录领取时使用的账户；二维码不含兑换码。卡片的固定标签与提示语会随设备语言显示，服务名称使用下载时选择的语言。若钱包下载暂不可用，可稍后重试；已经成功领取的额度不受影响。

技术教程 AI 短视频变现：帮客户做视频收服务费，客户自助用 API 你拿分销

短视频依然是流量之王，而 AI 视频生成正在把制作门槛砸到地板：以前做一条产品广告要找专业团队，现在用 AI 视频 API 几十秒就能出片。

这里有两条能同时拿的收入线：

  1. 帮客户做 AI 视频，收服务费（你的手艺）
  2. 引导客户自助用 API，你拿分销佣金（长期复利）

今天讲清楚怎么把这两件事一起做了。

为什么 AI 视频是眼下的好机会

需求端： 中小商家最缺短视频内容——餐饮要探店、电商要产品展示、教育要课程预告、中介要楼盘介绍。他们有需求，但请不起专业团队。

供给端： Ace Data Cloud 把主流 AI 视频模型统一到一个 API 里：

模型 特长 适用场景
Sora OpenAI 出品，画面电影级 品牌宣传片、创意广告
Veo Google 出品，自然真实 产品展示、生活场景
Luma 运动流畅、3D 感强 科技产品、动态效果
Seedance 字节出品，人物/动作强 人物展示、时尚内容
Hailuo MiniMax 出品，中文场景好 中文语境营销
Kling 快手出品，性价比高 日常商业视频
Pika / Pixverse 风格化、特效突出 创意/二次元短视频

再配上 AI 图片（gpt-image-2、Midjourney、Flux、Seedream），你可以同时输出视频封面、产品海报、社媒配图。

一句话：你能用很低的成本，做出以前需要团队才能完成的视频内容。 一个平台、一个 API Key 打通所有模型，切换模型只改一个参数。

第一条线：视频制作服务费

本地餐饮/奶茶/美容店、电商卖家、教育培训机构、房产中介/装修公司、自媒体和 MCN 机构。

实战案例：帮奶茶店做抖音内容

一次交付里，你的成本主要是自己的时间和很低的 API 费用，报价空间取决于你交付的质量和当地市场，别硬套别人的数字。

  • 线下扫街： 到附近商业街，进门问”老板，需要拍抖音短视频吗？我用 AI 帮你做，快又省”，带手机现场展示样片。

  • 行业解决方案： 打包”AI 餐饮营销方案””AI 电商内容方案”，提高客单价。

为什么选 Ace Data Cloud

  • 全模型覆盖： 主流 AI 视频/图片模型一个平台打通，不用分别注册十几个账号
  • API 标准化： 学会一个就能用所有模型，切换只改一个参数

  • 分销成熟： 邀请链接一键生成，佣金自动计算，后台实时查看

API 开发教程 VS Code：GitHub Copilot BYOK 接入 Ace Data Cloud

GitHub Copilot 官方 BYOK 文档将 VS Code 列为支持的本地客户端，并支持 OpenAI-compatible Provider。VS Code 版本、企业策略和模型可见性会影响最终 endpoint；首次接入请按下文检查实际请求。

配置范围

  1. 确认你的 GitHub Copilot 账户或组织已启用 BYOK/Custom Models 功能。
  2. 在 VS Code 的 Copilot 模型管理中新增 OpenAI-compatible Provider。
  3. Base URL 填写 https://api.acedata.cloud/v1。
  4. API Key 填写你的 Ace Data Cloud API Token。
  5. Model 填写模型目录中与所选协议兼容的精确模型 ID。
  6. 在 Copilot Chat 中发送 Reply only OK，再测试一次带工作区上下文的请求。

当前边界

  • Copilot App、CLI、GitHub Desktop、Enterprise BYOK 与 VS Code 的配置合同不同，本指南不把其他客户端步骤直接套用到 VS Code。
  • 组织策略可能禁止个人添加 Provider 或模型。
  • Tab completion、Chat、Agent 与后台任务可能使用不同模型路径，应分别验证。

API 开发教程 ADSL 代理对接说明

在爬虫与反爬虫斗争愈演愈烈的情况下，各大网站和 App 的风控检测越来越强，其中一项就是 IP 封禁。

为了解决 IP 封禁的困扰，一个有效的方式就是设置代理，设置代理之后，爬虫可以借助代理的 IP 来伪装自己的真实 IP 地址，从而突破反爬虫的限制。

但代理的质量有高有低，比如市面上的免费代理，几乎绝大多数都是不可用或者被封禁的状态，而有些付费普通代理也陆续被加入了各大网站和 App 的风控黑名单。因此，现在可以用作高质量数据爬爬取的代理越来越少了，目前市面上质量较高的代理主要有独享代理、ADSL 代理、移动蜂窝代理这几种类型。

本代理服务就是基于 ADSL 搭建的轮换代理服务，本文档会介绍此服务的申请和使用方法。

ADSL 代理介绍

ADSL，英文全称是 Asymmetric Digital Subscriber Line，即非对称数字用户环路。ADSL 通过拨号的方式上网，拨号时需要输入 ADSL 账号和密码，每次拨号就更换一个 IP。IP 分布在多个 A 段，如果 IP 都能使用，则意味着 IP 量级可达千万。

基于 ADSL 方式搭建的代理相比机房搭建的普通代理来说，有两个优势：一是线路基本都是移动、联通、电信，更贴近于居民日常上网线路，所以 IP 被封禁的概率会低一些。二是 IP 量级大，IP 量级越大，每个 IP 被封禁的概率就越小。

本代理服务背后是基于一个大规模的 ADSL 代理池，主要覆盖中国线路，线路主要来自移动、联通、电信等拨号 VPS 服务器，覆盖中国 100 多城市，出口 IP 约每日 30 万。支持市面上几乎所有网站和 App 的数据请求，代理质量很高，能够很大减小风控概率。

申请方法

要使用 ADSL 服务，可以首先到「申请页面」进行申请，首次申请有 1 积分免费额度，约 17.5MB。

如果您尚未登录，则会自动跳转到登录页面，登录之后继续申请即可。

申请完毕之后，可以到「控制台」中查看本人的申请结果，如图所示：

点击 「Credentials」，即可查看使用 ADSL 代理服务的用户名及密码，以冒号分隔，其中用户名是 8 位，密码是 32 位，如图所示：

本 ADSL 代理是一种轮换代理，因此使用的时候只需要设置一个固定的代理地址和端口即可，代理的地址和端口分别是 adsl.proxy.acedata.cloud 和 30005，是 HTTP/HTTPS/SOCKS 协议的代理，可以用于访问 HTTP 和 HTTPS 协议的网站。
